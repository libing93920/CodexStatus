# 胶囊置顶诊断

Windows 上的额度胶囊自动将 `capsule-diag` JSON 行写入现有 `<userData>/diag/diag.log`，沿用日志轮转和 `CODEX_STATUS_DIAG=0` 总开关。灵动岛开关不影响该诊断。

当胶囊被其他窗口盖住时，记录发生时间，并通过应用现有的“打开日志文件夹”入口取出 `diag.log`；如果已轮转，同时保留 `diag.log.old`。优先在移动遮挡窗口、重新显示胶囊或重启应用之前记录时间，便于定位故障状态。

## 记录内容

- `hwnd`、`seq`、`at`：胶囊句柄、本次运行的日志序号和采集时间。
- `events`：显示、隐藏、焦点、移动、缩放、置顶变化事件的合并计数与首次/末次时间。
- `electron`：Electron 看到的可见、焦点、置顶、最小化状态及 `boundsDip`。
- `native.capsule`：Win32 实际窗口状态，`topmost` 来自 `WS_EX_TOPMOST`；读取失败时为 `null`，并记录 `styleError`。
- `native.foreground`、`native.taskbar`：前台窗口、主任务栏的句柄、进程 ID、窗口类名、状态和边界。
- `native.overlapCandidates`：Z 顺序在胶囊前面、可见且矩形与胶囊重叠的窗口，最多 3 个。
- `native.scanned`、`native.reachedCapsule`：本次枚举检查数和是否到达胶囊；未到达时不能据空候选列表认定没有遮挡。
- `nativeStatus`、`probeError`：探测器启动、就绪、不可用或已停止状态及失败原因。
- `requestedAt`、`nativeElapsedMs`：请求时间及往返耗时，帮助判断原生数据与 Electron 状态的时间差。
- `sinkDropped`：慢磁盘导致未写入的采样数量；下一次获得写入名额时报告。

原生 `boundsPx` 为物理像素，Electron `boundsDip` 为 DIP，不能直接比较。窗口信息不包含标题、文档名、网页地址或页面内容。

## 判断边界

`native.capsule.topmost=false` 是原生置顶属性已丢失的证据；仅凭它不能确定由谁、在哪个调用中取消了置顶。应结合焦点事件、前后采样和其他窗口状态分析。

`topmost=true` 且存在 `overlapCandidates` 表示存在层级在前的矩形重叠候选。透明窗口、异形窗口、阴影和窗口区域可能让矩形重叠并不形成实际视觉遮挡；日志不把候选直接判定为遮挡原因。

采样不是原子快照，枚举期间窗口可能变化。每 2 秒一次的采样也可能错过短暂故障；Electron 置顶事件按开启/关闭分别计数，以保留采样间的事件线索。

## 开销与生命周期

仅启动一个隐藏的 PowerShell 原生探测子进程，每 2 秒最多一个在途请求，每次最多枚举 512 个窗口。隐藏胶囊在无事件时仅心跳采样；状态变化或窗口事件才写日志，稳定状态每 60 秒写一次。

高频移动和缩放事件仅更新固定种类计数，不逐事件写磁盘。写入沿用异步日志系统，最多 2 个待完成批次。子进程启动或请求超过 15 秒、输出异常或退出时记录失败并停止原生探测，继续保留 Electron 状态，不自动重试。关闭诊断、销毁胶囊或退出应用时清理监听、定时器与子进程。

诊断不会调用重新置顶、显示、激活或移动窗口的 API，也不会改变胶囊的展示策略。
